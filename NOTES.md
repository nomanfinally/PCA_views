# Architecture notes

- **Static deployment:** React + TypeScript + Vite; no database or runtime server. Relative build URLs support GitHub Pages repository paths. Files are read in a disposable Web Worker, processed in memory, and never uploaded or persisted.
- **Plot-first layout:** Dataset metadata, eigenvalues, and warnings live in the 42 px top bar. A 37 px toolbar places tools at the upper left and axes/search to the right; the remaining area is a full-width plot with a compact floating legend. Display settings, point editing, and the sample table open as overlays instead of consuming permanent plot area. On narrow screens tools scroll horizontally in a separate row and the legend starts collapsed on phones.
- **Reference behavior:** Tools were reviewed against [Vahaduo g25views](https://github.com/vahaduo/g25views) and the local `01_github_alt/smartPCA-views` implementation. The code is an independent implementation. Vahaduo's separate base/projected layer controls become dataset/population controls here: `.evec` contains one already computed PCA and does not identify a separate projected layer. G25 coordinate reprojection and its regional reference datasets are outside this viewer's input model.
- **Domain model:** `viewState.ts` owns a pure reducer for axes, visibility, population styles, row-specific fill/outline/shape/size/marks, selection, and display settings. `geometry.ts` implements convex hulls, centroids, regression, and fit ranges. `plotModel.ts` composes traces, shapes, and annotations without coupling to React or DOM events. New tools should extend these contracts before adding UI.
- **Identity and inheritance:** Row keys are independent of sample names. Population color/shape defaults apply to a population; sample fill, shape, size, and outline overrides take precedence. `markerAppearance` resolves inheritance for plot, editor, legend, and export. Hollow markers use transparent fills with explicit outlines because Plotly open-symbol rendering ignores independent outline colors. Red marks are separate from colors and transient box/lasso selections. Left-click toggles marks; right-click opens the editor without changing the mark. Closing a point editor keeps its mark. Population hiding preserves its legend entry and all styling. Resetting population style preserves its visibility.
- **Geometry:** Hulls and regression use currently filtered points on the selected axes. Hulls omit duplicate/interior points and require three non-collinear coordinates. With hulls enabled, exactly two distinct visible points produce one connecting line (also for vertical pairs), with hull opacity unless regression is explicitly enabled. Coincident pairs produce no line. Regression is ordinary least squares y on x; constant-x populations have no such line. These are descriptive overlays, not confidence regions or significance tests.
- **Viewport:** Wheel events are normalized across pixel/line/page delta units, coalesced per animation frame, and zoom around the cursor. Wheel, toolbar zoom, resize, and render operations share a queue. Superseded renders are skipped and axis ranges are read at execution time to avoid stale redraws. Numeric zoom limits prevent collapsed ranges. Native double-click axis reset is disabled so repeated marking clicks cannot change the viewport. Axis changes reset the viewport; appearance and visibility edits preserve it. Fit visible samples fits the current filtered rows; Reset axes fits the complete source dataset. Equal axis scale enforces equal coordinate units; The aspect ratio setting constrains the canvas shape to Full span, 1:1, 16:9, 4:3, 3:2, 4:5, or 9:16. These are distinct controls.
- **Labels:** A single toolbar tool cycles off/plain/background/boxed. Centroid connectors are independent globally and per population. Invisible Plotly arrows retain draggable annotation tails when connectors are off. Population and individual IID callouts use namespaced annotation identities; individual identities use row keys so duplicate IIDs stay independent. Offsets are keyed by identity and PC pair and archived with the viewport. Old population offset keys are still read. Label content is escaped before passing it to Plotly.
- **Sample interaction:** Pointer hit testing uses the current rendered axes and visible rows, independent of Plotly hover events. Both SVG and WebGL support click-to-mark and right-click editing even with hover disabled. A moved/cancelled pointer never marks a sample. Tool cursor rules target the plotting drag surface while leaving label dragging separate.
- **Selection events:** Plotly emits empty selection events during programmatic redraws. Only events carrying a box range or lasso geometry replace the workspace selection. Clearing is explicit so the selection actions remain available after rendering highlight rings.
- **Resize lifecycle:** A component-owned ResizeObserver resizes the chart. Plotly resize returns a promise despite its upstream void type; the adapter adopts it and handles removal during pending resize. Renderer updates are serialized, and workers/renderers are disposed on replacement.
- **Exports:** `PcaPlot.capturePng` freezes current ranges, domains, dimensions, styles and label offsets in an offscreen renderer. The live heading is removed by reducing only its outer margin, preserving inner plot pixels. `composePng` adds canvas headings and a measured, tightly fitted legend outside this immutable image. `arrangeImage` is the pure placement function; chart size never depends on legend size. The snapshot records the rendered axis frame and tick/title bounds. Legend positions anchor to that frame, with clearance for axis text; image margins and heading width do not determine its alignment. PNG uses 2× resolution; preview and download share the exact same image. Population swatches reuse `MarkerSwatch` and ignore individual overrides. Preview updates are debounced and stale results are discarded. Output size is limited to 16,000 pixels per edge and 64 million pixels. CSV includes all PCs for filtered/selected rows and escapes spreadsheet formulas in names.
- **Interactive archives:** `archive.ts` serializes the complete dataset/reducer, viewport and label offsets with a versioned schema. `archivePlugin` produces a separate IIFE runtime containing React, both Plotly renderers and CSS, fetched only when HTML is requested. Exports inject escaped JSON plus inline code/styles. An archived viewer can export another archive from its inline runtime without network access. Standard websites use a parser worker; offline HTML uses the same parser directly when loading a new file, since file URLs cannot load the website worker. Large offline imports can briefly block the UI. The archive contains hidden populations and all sample rows. No runtime state is automatically persisted to disk.
- **Input preservation:** Source `.evec` files are read-only and ignored by Git. Numeric population labels are accepted as the last token. Coordinate/header counts are validated. Duplicate IDs are retained and reported. Axis percentages use the loaded eigenvalue sum until a known total is supplied; this distinction is explained in Variance settings rather than repeated in each axis title. `.eval` headers are checked against the current dataset. Hover IID comes from sample.id; FID comes from sample.population, with no separate metadata join.
- **Limits:** 50 MB file cap is a memory safeguard, not a performance guarantee. SVG is used up to 5,000 samples; larger datasets require WebGL. Dense labels and many hulls can be expensive. The table pages 50 rows and the legend reveals large lists in batches of 100. Source samples never enter `public/` or `dist/`.
- **Extension points:** Additional importers can produce `Dataset`; metadata joins should use explicit identifiers. Larger datasets can move to typed buffers and worker filtering. Session serialization, additional export formats, and dataset comparisons can build on the reducer and pure plot-model boundary.

- **Popover interaction:** Context editors trap keyboard focus while open, return focus to their trigger on Escape/close, and recalculate their position when content or viewport dimensions change.

- **Reference comparison:** See [feature recommendations](docs/REFERENCE_COMPARISON.md) for specific capabilities verified in the older viewer and proposed extensions.

- **Marker composition:** Population marker shape, treatment, and varied-shape presets are independent. Preset ordinals come from original dataset order, so filtering never changes a sample's assigned shape. Explicit sample overrides take precedence. Fill and boundary opacity are encoded separately in RGBA colors; Plotly marker opacity stays at 1 to avoid multiplying boundary and fill transparency together.
- **UI extension points:** `PopulationEditor` owns the compact/common versus collapsible controls; `StyleControls` shares legend layout and ratio inputs; `SettingsDialog` owns the tabbed global settings interface (Chart first), hover, eigenvalue import, and variance controls. Only the selected section is mounted; values remain in the reducer. Both the toolbar settings button and legend gear open this shared dialog. Tabs activate on click or Enter/Space; arrow keys move focus, and Escape restores focus to the opener. `ExportPanel` owns the separate export dialog and automatic composition preview. Plot geometry and export layout remain pure domain functions.

- **Defaults and reset:** `initialView(dataset)` initializes Solid colors and filled circles through eight populations, otherwise filled shapes. View state retains population ordering for repeatable defaults. A full reset recreates the reducer state and plot instance, clearing zoom, offsets, filters and style edits while retaining source data. Archived settings override application defaults at load.
- **Plot backgrounds:** white/light gray/ivory/ice blue/lavender/charcoal presets and custom colors affect only the plotting box. Grid, zero-line and frame colors derive from background brightness. The live plot, immutable PNG capture and HTML archive use the same setting.
